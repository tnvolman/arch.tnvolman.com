Privacy Policy

This policy describes how Arch — the theological review API at arch.tnvolman.com, operated by The Forge — collects and uses information when you request an API key, sign in to the developer dashboard, attach a payment method, call POST /v1/review, or email us.

Effective Date: 24 July 2026  ·  Last Updated: 13 September 2026

Who this covers

This policy applies only to the public Arch API product on arch.tnvolman.com: the marketing pages, the “Get API Key” form, the developer dashboard, billing setup, and the review API. It does not apply to other sites or products we operate.

Arch is a review layer. It returns APPROVED, FLAGGED, or REJECTED with Scripture evidence. It does not write, preach, counsel, or speak to your users.

Information we collect

API key request

The landing-page form posts to /arch/request-access. We require full name and email. You may also provide company or app name and a use-case description. Those four fields are stored with the issued key.

The form also asks for estimated monthly review volume and sends a consent flag, consent version (privacy-2026-07-24), and consent timestamp from your browser. Volume is used only as a form field on the page; the access endpoint does not persist volume, the consent flag, or the consent timestamp on the key record.

We issue an API key immediately (arch_live_…). The secret is shown once in the browser and emailed to you. We store a hash and prefix of the key, not the full secret, along with name, email, company, use case, a starter volume tier, and status (active, suspended, or revoked).

Developer dashboard (email magic link)

If you enter the email used for access, we post to /arch/dashboard/login and, when that email has an active key, email a one-time login link that expires in one hour. The response does not tell a caller whether the email has a key. After you open the link, we set an HTTP-only arch_dash cookie (SameSite=Lax, up to 7 days) so you can view usage, rotate the key, and start Stripe billing setup. You can log out, which clears the cookie.

Billing

Paid reviews require a card on file. We send you to Stripe Checkout (setup mode) to attach a payment method. We store a Stripe customer id and default payment-method id. Stripe handles card numbers; we do not store full card data. Each charged review writes a ledger row with payment-intent id, amount, currency, status, and the character count of the submitted text — not the text itself. Stripe metadata on the charge includes character count and an internal key id.

Review API

POST /v1/review (and the legacy /api/archguard/review alias) accepts an X-API-Key header and a JSON body with the text to review (up to 50,000 characters), plus optional max_tokens, payment_method_id, and an idempotency key. We send that text through the Arch review pipeline to produce a verdict. We increment call count and last-used time on your key. Operational logs record request size (character count), not the full submitted text. Rate limits apply per API key (60 requests per minute on the public spec).

Contact email

If you write to api@tnvolman.com or sanctuary@tnvolman.com, we receive whatever you send in that message.

Technical data

We use your IP address to rate-limit key issuance. The site is served through Cloudflare and hosted on Railway; those providers see standard request metadata (IP, user agent, timestamps). Marketing pages load fonts from Google Fonts. We do not run a third-party advertising pixel or analytics tag on these pages.

How we use information

  • Issue, authenticate, rotate, suspend, or revoke API keys
  • Email your key and dashboard magic links (via SendGrid, from sanctuary@tnvolman.com)
  • Notify the operator at sanctuary@tnvolman.com when a key is issued (name, email, company, use case, key prefix)
  • Charge per review through Stripe and show recent charges on the dashboard
  • Produce a theological verdict for the text you submit
  • Prevent abuse (rate limits) and answer support mail

There is no subscription. Billing is pay-per-call after you attach a card. We do not sell your information. We do not use Arch account or review data for advertising.

Who we share with

  • Stripe — customer record, payment method, and per-review charges
  • SendGrid — transactional email (API key delivery and magic links)
  • Cloudflare — CDN and edge for arch.tnvolman.com
  • Railway — application hosting
  • Google Fonts — typefaces on the marketing pages

Submitted review text is processed by the Arch review pipeline in order to return a verdict. We do not sell that text. The charge ledger stores character count, not the text.

Cookies

The only first-party cookie Arch sets is arch_dash, after a successful magic-link login. It is HTTP-only and used solely for the developer dashboard. Cloudflare may set cookies for security at the edge. We do not set advertising cookies.

Retention and your choices

Key records and charge history are kept while we need them to operate the API, bill usage, and handle support. Magic-link tokens are single-use and expire after one hour. The dashboard cookie lasts up to seven days or until you log out.

You can rotate your key from the dashboard, stop calling the API at any time, or email us to correct account details or ask us to suspend or revoke a key. For access or deletion requests, write to api@tnvolman.com.

Children

Arch is a developer API. It is not directed at children, and we do not knowingly collect information from anyone under 16.

Changes

If this policy changes, we will update the Last Updated date on this page. The access form currently sends consent version privacy-2026-07-24 with the key request.

Contact

Questions about this policy or your Arch account: api@tnvolman.com. Operational mail for keys and dashboard links is sent from sanctuary@tnvolman.com.
